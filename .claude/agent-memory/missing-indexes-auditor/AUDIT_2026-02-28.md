# Missing Firestore Indexes Audit — 2026-02-28

## Executive Summary

**Status:** 17 critical missing indexes identified and added to `firestore.indexes.json`

**Impact:** These missing indexes would cause FailedPrecondition errors in production for:
- Admin operations (suspend_seller, delete_account, delete_payment_provider)
- Cron jobs (check_expired_authorizations, renewal reminders, alert cleanup)
- Checkout idempotency checks
- Stock notification subscriptions
- Security alert deduplication

## Methodology

1. Read existing `firestore.indexes.json` (109 indexes before audit)
2. Scanned all Python handlers in `functions/handlers/*.py` for composite queries
3. Scanned Flutter providers in `origna_gta/lib/features/**/*.dart`
4. Identified queries with:
   - 2+ `where()` clauses on different fields
   - `where()` + `orderBy()` on different fields
   - `array_contains` + any other filter
   - `whereIn` on multiple fields
5. Cross-referenced against existing indexes

## False Positives (Queries That Don't Need Indexes)

During the audit, the following patterns were identified as NOT requiring composite indexes:

1. **Single field equality + limit** — uses automatic single-field index
2. **Document ID lookup** — uses primary key
3. **Subcollection queries with implicit parent filter** — parent document ID counts as first field

Example (does NOT need composite index):
```dart
.collection('orders')
.where('userId', isEqualTo: uid)  // Single field
.orderBy('createdAt', descending: true)  // Same field or automatic
```
