### Audit Findings for Return Request Flow

#### 1. Digital Products: Stock Not Restored, License Not Invalidated

*   **Severity:** MEDIUM
*   **File and Line:** `functions/handlers/orders.py`, `_apply_refund_atomically` function (around line 1030 in the full file content).
*   **Invariant Violated:** While digital product return *requests* are correctly blocked, and stock is not restored for digital items during refunds, there's no explicit mechanism to invalidate or revoke the digital license itself when a digital product is refunded (e.g., if an admin manually processes a refund).
*   **Recommended Fix:** Implement a system to invalidate or mark digital licenses as refunded/inactive in the `licenses` collection when a refund for a digital product is processed. This would ensure that refunded digital products can no longer be accessed.

#### 2. Buyer Manual Escalation Path to Admin is Missing

*   **Severity:** MEDIUM
*   **File and Line:**
    *   `functions/schema_constants.py`, `ReturnStatusValues` (lines 836-848 in Python file).
    *   `functions/models/return_request.py`, `ReturnRequest` (lines 44-48 in Python file).
    *   `functions/schema_constants.py`, `BusinessRules` (line 1047 in Python file).
*   **Invariant Violated:** The system includes an automated process for escalating unresolved return requests (`ESCALATED` status, `RETURN_ESCALATION_DAYS`), but there is no explicit user-initiated path for a buyer to manually escalate a disputed return directly to an administrator. This could lead to buyer frustration if a resolution is delayed or unsatisfactory.
*   **Recommended Fix:** Create a Cloud Function (e.g., `escalate_return_request`) that allows buyers to manually trigger an escalation. This function should:
    1.  Verify the request's authenticity and the buyer's ownership of the return.
    2.  Check the return's current status for eligibility for manual escalation.
    3.  Transition the return status to `ESCALATED`.
    4.  Populate `escalatedAt` and `escalationReason` fields with relevant information (e.g., "manual_buyer_escalation").
    5.  Trigger notifications to administrators about the newly escalated return.
